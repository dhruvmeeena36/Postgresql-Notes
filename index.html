1. PostgreSQL Overview

What is PostgreSQL?

PostgreSQL (Postgres) is a free, open-source, object-relational database management system (ORDBMS). It stores data in tables and uses SQL to manage data.

Used by Instagram, Reddit, Apple, Spotify — trusted at massive scale.
Simple rule: Postgres = jab complex query, JSON, joins, index, aur reliable data integrity chahiye.

Why Use PostgreSQL?

  • 100% free and open-source
  • Full ACID compliance — data is always safe
  • Handles complex queries beautifully
  • Built-in JSON/JSONB — acts like NoSQL too
  • Advanced features: Window functions, CTEs, Triggers
  • Runs on Linux, Windows, macOS

Key Features

ACID

Atomicity, Consistency, Isolation, Durability — data integrity guaranteed.

MVCC

Multiple users read/write simultaneously without blocking each other.

JSON/JSONB

Store and query JSON like a NoSQL DB. JSONB is binary and faster.

Indexes

B-Tree, Hash, GIN, GiST, BRIN — multiple types for different queries.

Extensions

PostGIS (geo), pg_trgm (fuzzy search), uuid-ossp and 100+ more.

Full-Text Search

Built-in search engine with ranking, stemming, and language support.

4. CRUD Operations

SELECT — Read Data

SELECT * FROM students; -- all rows, all columns SELECT first_name, course FROM students; -- specific columns SELECT DISTINCT course FROM students; -- unique values only SELECT first_name AS "Name" FROM students; -- column alias SELECT * FROM students WHERE gender = 'F'; -- with condition

INSERT — Add Rows

-- Single row INSERT INTO students (first_name, last_name, email, age, gender) VALUES ('Karan', 'Mehta', 'karan@mail.com', 24, 'M'); -- Multiple rows INSERT INTO students (first_name, email, age, gender) VALUES ('Anjali', 'anjali@mail.com', 21, 'F'), ('Mohan', 'mohan@mail.com', 22, 'M');

UPDATE — Modify Rows

-- Update single column UPDATE students SET course = 'Cybersecurity' WHERE student_id = 4; -- Update multiple columns UPDATE students SET course = 'Web Dev', fee_paid = 40000.00 WHERE student_id = 3;
Always use WHERE in UPDATE! Without it, ALL rows are updated.

DELETE — Remove Rows

DELETE FROM students WHERE student_id = 2; -- specific row DELETE FROM students WHERE is_active = FALSE; -- condition-based TRUNCATE TABLE students; -- removes all rows fast

5. Filtering and Sorting

WHERE + Operators

WHERE age > 20 WHERE age > 20 AND gender = 'F' WHERE age > 20 OR course = 'CS' WHERE course IN ('CS', 'DS', 'AI') -- cleaner than multiple ORs WHERE course NOT IN ('Undecided') WHERE fee_paid BETWEEN 40000 AND 50000 -- inclusive on both ends WHERE course IS NULL WHERE course IS NOT NULL

LIKE & ILIKE (Pattern Match)

-- % = any chars, _ = one char WHERE name LIKE 'A%' -- starts with A WHERE name LIKE '%n' -- ends with n WHERE name LIKE '_r%' -- 2nd char is r WHERE name ILIKE 'ar%' -- case-insensitive
ILIKE is PostgreSQL-specific. MySQL doesn't have it.

ORDER BY, LIMIT, OFFSET

ORDER BY age ASC -- youngest first ORDER BY fee DESC -- highest first ORDER BY course, age DESC -- multi-col sort LIMIT 5 -- first 5 rows LIMIT 5 OFFSET 10 -- rows 11-15 -- Pagination (page 2, 10 per page): LIMIT 10 OFFSET 10

Join ka simple funda

Join ka matlab: do tables ko related column se jodna. Usually students.dept_id aur departments.dept_id jaisa common column hota hai.

Yaad rakh: INNER = sirf match, LEFT = left sab, RIGHT = right sab, FULL = dono side ke sab rows.

JOIN example yaad rakhne ka trick

Left table = students, right table = departments. Agar sirf matching dekhni ho to INNER JOIN, agar students sab chahiye to LEFT JOIN. Departments sab chahiye to RIGHT JOIN. Dono sab chahiye to FULL OUTER JOIN.

INNER JOIN

Sirf wohi rows aayengi jahan students aur departments dono me match hai. Jis student ka dept_id nahi mila, woh bahar.

SELECT s.name, d.dept_name FROM students s INNER JOIN departments d ON s.dept_id = d.dept_id
INNER JOIN = “match mila to hi row dikhao”. Interview me isko sabse pehle yaad rakhna.

LEFT JOIN

Left table ke saare students aayenge. Dept mila to naam, nahi mila to NULL. Isliye left join me left table safe hoti hai.

-- Students ko department ke saath dikhao SELECT s.name, d.dept_name FROM students s LEFT JOIN departments d ON s.dept_id = d.dept_id; -- Jis student ka department assign nahi hai, woh bhi dikhega SELECT s.name, d.dept_name FROM students s LEFT JOIN departments d ON s.dept_id = d.dept_id WHERE d.dept_name IS NULL;

8. Subqueries & Nested Queries

What is a Subquery?

Hinglish me: ek query ke andar doosri query. Pehle inner query chalti hai, phir uska result outer query use karti hai. Jab direct answer ke liye pehle calculation chahiye ho, tab subquery ka use hota hai.

Simple Subquery

-- Students jo average se zyada fee pay kar rahe hain SELECT first_name, fee_paid FROM students WHERE fee_paid > ( SELECT AVG(fee_paid) FROM students ); -- Samjho: inner query average nikaal rahi hai, outer query compare kar rahi hai

Subquery with IN

-- Sirf wahi students jo valid departments me hain SELECT first_name FROM students WHERE dept_id IN ( SELECT dept_id FROM departments ); -- Agar list ke andar value mil jaaye to row aati hai

Subquery in FROM (Derived Table)

-- Pehle group by ka result banao, phir uspar filter lagao SELECT summary.course, summary.total FROM ( SELECT course, COUNT(*) AS total FROM students GROUP BY course ) AS summary WHERE summary.total > 1; -- Derived table = temporary table jaisa, bas query ke andar

Correlated Subquery Slightly Advanced

Samjho: ye har row ke liye outer query se value uthata hai. Isliye slow ho sakta hai, especially badi tables par.

-- Har course ke average se zyada pay karne wale students SELECT first_name, course, fee_paid FROM students s1 WHERE fee_paid > ( SELECT AVG(fee_paid) FROM students s2 WHERE s2.course = s1.course -- outer row ko refer kar raha hai ); -- Ye correlated hai kyunki inner query s1.course ka use kar rahi hai
Agar performance issue aaye, to CTE ya JOIN ke saath solution socho.

Hinglish tip: read fast hoti hai, but write slow ho sakti hai. Isliye har column pe index mat lagao.

Views & Materialized Views

-- View = Data actually store nahi hota Har baar query run hoti hai → latest data milta hai CREATE VIEW active_students AS SELECT * FROM students WHERE is_active = TRUE; SELECT * FROM active_students; -- Materialized View = Query ka result physically store hota hai , Fast read ✅ , but Manually refresh karna padta hai CREATE MATERIALIZED VIEW mv_stats AS SELECT course, COUNT(*) FROM students GROUP BY course; REFRESH MATERIALIZED VIEW mv_stats;
View = live query. Materialized view = cache jaisa. Fast read, but refresh karna padta hai.

Transactions — BEGIN / COMMIT / ROLLBACK

-- Transaction = sab kuch ek saath execute hota hai BEGIN; UPDATE accounts SET balance = balance - 5000 WHERE id = 1; UPDATE accounts SET balance = balance + 5000 WHERE id = 2; COMMIT; -- dono changes save
-- Agar mistake ho jaye to rollback BEGIN; INSERT INTO students ...; SAVEPOINT sp1; -- checkpoint bana diya INSERT INTO students ...; -- Sirf second step undo karna ho ROLLBACK TO sp1; COMMIT;
Bank transfer ka classic example: paise yahan se gaye aur wahan na पहुंचे, aisa nahi hona chahiye.

Stored Procedures — Procedure Ka Use

Procedure ka use tab hota hai jab multiple SQL steps ek jagah group karne ho. Function se difference ye hai ki procedure value return zaroori nahi karta, aur CALL se chalaya jata hai.

-- Procedure bana rahe hain: fee update karne ke liye CREATE OR REPLACE PROCEDURE increase_fee(student_id INT, bonus NUMERIC) LANGUAGE plpgsql AS $$ BEGIN UPDATE students SET fee_paid = fee_paid + bonus WHERE student_id = increase_fee.student_id; END; $$; -- Procedure ko call karna CALL increase_fee(3, 1500);
Exam line yaad rakho: Procedure = CALL, Function = SELECT.

CTEs — WITH Clause

-- CTE = temporary named result set. Code clean aur readable hota hai. WITH top_students AS ( SELECT * FROM students WHERE fee_paid > 40000 ) SELECT * FROM top_students ORDER BY fee_paid DESC; -- Multiple CTEs WITH cs AS (SELECT * FROM students WHERE course = 'CS'), ds AS (SELECT * FROM students WHERE course = 'DS') SELECT * FROM cs UNION ALL SELECT * FROM ds;
CTE ko temporary naam wala result samajh. Jab query badi ho jaye, CTE se code neat ho jata hai.

Window Functions Interview Favourite

-- Window function = row preserve hoti hai, calculation saath me hota hai SELECT name, fee_paid, ROW_NUMBER() OVER(ORDER BY fee_paid DESC) AS rn, RANK() OVER(ORDER BY fee_paid DESC) AS rnk, DENSE_RANK() OVER(ORDER BY fee_paid DESC) AS drnk FROM students; -- Partition: har course ke andar alag ranking RANK() OVER (PARTITION BY course ORDER BY fee_paid DESC) -- Running total SUM(fee_paid) OVER (ORDER BY student_id)
Window function me rows disappear nahi hoti — har row ka result preserve hota hai. Interview me ye line bolna important hai.

JSONB Basics

-- JSONB = structured data ko store karne ka strong way details JSONB -- Insert INSERT INTO products (name, details) VALUES ('Laptop', '{"brand":"Dell","ram":16}'); -- -> text deta hai, -> JSON object deta hai SELECT details ->> 'brand' FROM products; -- Filter WHERE details @> '{"ram":16}' -- Query fast karne ke liye GIN index bhi laga sakte ho
