1. PostgreSQL Overview

What is PostgreSQL?

PostgreSQL (Postgres) is a free, open-source, object-relational database management system (ORDBMS). It stores data in tables and uses SQL to manage data. Developed at UC Berkeley, maintained by global community since 1996.

Used by Instagram, Reddit, Apple, Spotify — trusted at massive scale.

Why Use PostgreSQL?

  • 100% free and open-source
  • Full ACID compliance — data is always safe
  • Handles complex queries beautifully
  • Built-in JSON/JSONB — acts like NoSQL too
  • Advanced features: Window functions, CTEs, Triggers
  • Runs on Linux, Windows, macOS

Key Features

ACID

Atomicity, Consistency, Isolation, Durability — data integrity guaranteed.

MVCC

Multiple users read/write simultaneously without blocking each other.

JSON/JSONB

Store and query JSON like a NoSQL DB. JSONB is binary and faster.

Indexes

B-Tree, Hash, GIN, GiST, BRIN — multiple types for different queries.

Extensions

PostGIS (geo), pg_trgm (fuzzy search), uuid-ossp and 100+ more.

Full-Text Search

Built-in search engine with ranking, stemming, and language support.

4. CRUD Operations

SELECT — Read Data

SELECT * FROM students; -- all rows, all columns SELECT first_name, course FROM students; -- specific columns SELECT DISTINCT course FROM students; -- unique values only SELECT first_name AS "Name" FROM students; -- column alias SELECT * FROM students WHERE gender = 'F'; -- with condition

INSERT — Add Rows

-- Single row INSERT INTO students (first_name, last_name, email, age, gender) VALUES ('Karan', 'Mehta', 'karan@mail.com', 24, 'M'); -- Multiple rows INSERT INTO students (first_name, email, age, gender) VALUES ('Anjali', 'anjali@mail.com', 21, 'F'), ('Mohan', 'mohan@mail.com', 22, 'M');

UPDATE — Modify Rows

-- Update single column UPDATE students SET course = 'Cybersecurity' WHERE student_id = 4; -- Update multiple columns UPDATE students SET course = 'Web Dev', fee_paid = 40000.00 WHERE student_id = 3;
Always use WHERE in UPDATE! Without it, ALL rows are updated.

DELETE — Remove Rows

DELETE FROM students WHERE student_id = 2; -- specific row DELETE FROM students WHERE is_active = FALSE; -- condition-based TRUNCATE TABLE students; -- removes all rows fast

5. Filtering and Sorting

WHERE + Operators

WHERE age > 20 WHERE age > 20 AND gender = 'F' WHERE age > 20 OR course = 'CS' WHERE course IN ('CS', 'DS', 'AI') -- cleaner than multiple ORs WHERE course NOT IN ('Undecided') WHERE fee_paid BETWEEN 40000 AND 50000 -- inclusive on both ends WHERE course IS NULL WHERE course IS NOT NULL

LIKE & ILIKE (Pattern Match)

-- % = any chars, _ = one char WHERE name LIKE 'A%' -- starts with A WHERE name LIKE '%n' -- ends with n WHERE name LIKE '_r%' -- 2nd char is r WHERE name ILIKE 'ar%' -- case-insensitive
ILIKE is PostgreSQL-specific. MySQL doesn't have it.

ORDER BY, LIMIT, OFFSET

ORDER BY age ASC -- youngest first ORDER BY fee DESC -- highest first ORDER BY course, age DESC -- multi-col sort LIMIT 5 -- first 5 rows LIMIT 5 OFFSET 10 -- rows 11-15 -- Pagination (page 2, 10 per page): LIMIT 10 OFFSET 10

8. Subqueries & Nested Queries

What is a Subquery?

A query written inside another query. Inner query runs first, its result is used by outer query.

Simple Subquery

-- Students paying more than average SELECT first_name, fee_paid FROM students WHERE fee_paid > ( SELECT AVG(fee_paid) FROM students );

Subquery with IN

-- Students in valid departments SELECT first_name FROM students WHERE dept_id IN ( SELECT dept_id FROM departments );

Subquery in FROM (Derived Table)

SELECT summary.course, summary.total FROM ( SELECT course, COUNT(*) AS total FROM students GROUP BY course ) AS summary WHERE summary.total > 1;

Correlated Subquery Slightly Advanced

References outer query for each row. Runs once per row — can be slow on large tables.

-- Students paying above their course's average SELECT first_name, course, fee_paid FROM students s1 WHERE fee_paid > ( SELECT AVG(fee_paid) FROM students s2 WHERE s2.course = s1.course -- references outer row );
Consider using CTEs or JOINs for better performance on large datasets.

9. Advanced PostgreSQL Topics

Indexes

CREATE INDEX idx_course ON students(course); CREATE UNIQUE INDEX idx_email ON students(email); DROP INDEX idx_course;
TypeBest For
B-Tree=, <, >, BETWEEN, ORDER BY
Hash= only
GINJSON, Arrays, full-text
BRINLarge ordered tables (logs)
Indexes speed reads, slow writes. Don't over-index!

Views & Materialized Views

-- Regular View (always live) CREATE VIEW active_students AS SELECT * FROM students WHERE is_active = TRUE; SELECT * FROM active_students; -- Materialized View (stored result) CREATE MATERIALIZED VIEW mv_stats AS SELECT course, COUNT(*) FROM students GROUP BY course; REFRESH MATERIALIZED VIEW mv_stats;
View = live. Mat. View = stored, faster but needs refresh.

Transactions — BEGIN / COMMIT / ROLLBACK

BEGIN; UPDATE accounts SET balance = balance - 5000 WHERE id = 1; UPDATE accounts SET balance = balance + 5000 WHERE id = 2; COMMIT; -- save both
BEGIN; INSERT INTO students ...; SAVEPOINT sp1; -- checkpoint INSERT INTO students ...; -- Undo only 2nd insert: ROLLBACK TO sp1; COMMIT;

CTEs — WITH Clause

-- Named temporary result WITH top_students AS ( SELECT * FROM students WHERE fee_paid > 40000 ) SELECT * FROM top_students ORDER BY fee_paid DESC; -- Multiple CTEs WITH cs AS (SELECT * FROM students WHERE course = 'CS'), ds AS (SELECT * FROM students WHERE course = 'DS') SELECT * FROM cs UNION ALL SELECT * FROM ds;
CTEs make complex queries readable. Exist only for the query duration.

Window Functions Interview Favourite

-- ROW_NUMBER, RANK, DENSE_RANK SELECT name, fee_paid, ROW_NUMBER() OVER(ORDER BY fee_paid DESC) AS rn, RANK() OVER(ORDER BY fee_paid DESC) AS rnk, DENSE_RANK() OVER(ORDER BY fee_paid DESC) AS drnk FROM students; -- Partition: rank within each course RANK() OVER (PARTITION BY course ORDER BY fee_paid DESC) -- Running total SUM(fee_paid) OVER (ORDER BY student_id)
RANK: 1,1,3 (skips after tie). DENSE_RANK: 1,1,2 (no skip).

JSONB Basics

-- Store JSON details JSONB -- Insert INSERT INTO products (name, details) VALUES ('Laptop', '{"brand":"Dell","ram":16}'); -- Query field (returns text) SELECT details ->> 'brand' FROM products; -- Filter WHERE details @> '{"ram":16}' -- -> returns JSON, ->> returns text
